# 徒歩圏データ受領までに進めたこと（2026年9月11日）

## アプリの更新

検索結果を買い物先・バス停に分け、総件数と「さらに表示」を追加した。各12件で打ち切っていた結果を最後まで確認できる。追加表示時は新しい結果の先頭へフォーカスを移し、キーボード操作を継続できる。

カタカナとひらがな、全角と半角の違いを吸収し、空白区切りの複数語をすべて含む検索に対応した。例は「こすもす 高栄」。施設は名称・市名・公式所在地、バス停は名称・事業者が対象。漢字の読み仮名変換、路線検索は行わない。検索をクリアするボタンを追加し、読み込み中と0件を区別する。

施設・国の停留所・OSM試作地点の詳細に「この場所のリンクをコピー」を追加。選択場所をURLにも反映し、再読み込みと共有リンクから復元する。コピーできない環境では選択できるURL欄を表示する。リンクのIDが不正・未収録なら案内を出して名前検索へ戻れる。施設リンクは通常マップ、試作停留所リンクは徒歩圏試作を開く。徒歩時間・速度・地図の拡大率・表示フィルターの状態は保存しない。

施設の読み込みを`useShoppingData`にまとめ、`useWalkingData`はその結果から既存の対象施設IDを選ぶようにした。地図と徒歩圏で別々の施設取得・状態管理を行わない。徒歩計算アルゴリズム、道路網、対象7地点・1施設、通常バス停4,418件と買い物先22件は維持する。

## 現在のID一覧

`scripts/export-integration-index.py`で、現在の公開データから下記のUTF-8 BOM付きCSVを生成する。全行に直接開く地図リンクを付けた。生成元のハッシュと件数は`manifest.json`に記録する。新しい徒歩圏データはまだ含まない。

|ファイル|件数|内容|
|---|---:|---|
|national-stops.csv|4,418|国の停留所ID、名称、原座標、事業者、路線、出典版、ライセンス|
|pilot-stops.csv|7|既存試作のOSM ID、名称、原座標。国の停留所への対応欄は未確認のため空欄|
|facilities.csv|22|施設ID、名称、市名、分類、形状区分、OSM ID、公式URL、出典日時、現行徒歩圏の対象かどうか|
|manifest.json|—|件数、各CSVと生成元ファイルのSHA-256、公開データURL|

保存場所はソースZIP内の`outputs/integration-ready-20260911/id-index/`。一覧と本書だけを含む連携資料ZIPも用意する。

## 現在の公開データと接続箇所

|対象|公開データ|アプリ側|
|---|---|---|
|通常のバス停|[review-national.geojson](https://yyy-yuichi.github.io/bus-stop-compact-town/data/review-national.geojson)|`stopCatalog.ts`の`nationalCatalog`、`BusStopLayer.tsx`|
|徒歩圏試作のバス停原資料|[bus_stop.geojson](https://yyy-yuichi.github.io/bus-stop-compact-town/data/bus_stop.geojson)|道路データの`pilot_stops[].id`に含まれる7地点だけ使用|
|買い物先の位置・形状|[shopping.geojson](https://yyy-yuichi.github.io/bus-stop-compact-town/data/shopping.geojson)|`shoppingData.ts`、`ShoppingLayer.tsx`。対応キーはGeoJSONの`feature.id`|
|従来の徒歩圏試作|[walking-onoda.json](https://yyy-yuichi.github.io/bus-stop-compact-town/data/walking-onoda.json)|`WalkingPanel.tsx`の取得・表示、`walking.ts`の計算|

施設形状はPointまたはMultiPolygon。GeoJSONの座標は経度・緯度の順。建物や代表点は出入口ではない。国の座標は元データのJGD2011を保持し、時点補正を行っていない。

国のID `mlit-p11-22-35:<原資料行>` は2022年度版内の識別子で、年度をまたぐ固定IDではない。OSMの`node/...`等とは別の名前空間であり、距離の近さだけで同じ乗り場として接続しない。施設IDの例は`sunpark`、`maruki-nakagawa`、`cosmos-onoda`。

受領後は、対象地域・出発点ID・座標系・5分/10分の区別・出典/利用条件を確認する。現在の試作は道路線を描画する構成なので、受領物がポリゴンや別形式の場合は、その内容に合わせた読み込み・表示処理を追加する。買い物先についても、範囲への包含表示と実際の入口までの経路・到達可否を区別する。

コーディネーターへの送信は行っていない。受領側の現状資料として保存する。

## 確認結果

場所リンクは現在の全4,447件（通常バス停4,418・試作7・施設22）でIDを往復検証した。不正なID、重複したパラメーター、長すぎる値も検証した。かな・全半角・複数語検索と12件を超える結果の取得を自動確認した。

ブラウザーでは施設・通常バス停・試作地点のリンク復元、コピー完了表示、未収録IDの案内を確認した。幅390pxの画面で検索の続き表示、追加結果へのフォーカス移動、Enterでの選択、再読み込みによる場所復元、ひらがなと所在地の複数語検索を確認した。既存の徒歩圏試作も5分・10分で操作し、画面エラーがないことを確認した。クリップボードが使えない場合の手動コピー欄は実装しているが、この環境では表示条件を実測していない。

ビルド、バス停データ検証、徒歩経路テスト、道路原資料の13テスト、公開ファイルの整合検証が成功した。CSVは保存後に全行を読み戻し、件数・IDの一意性・各セルを照合した。
