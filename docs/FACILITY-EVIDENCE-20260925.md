## Jevで何を効率化できたか

順序は **保存済み記事 → リンク一括取得 → Jevで資料・店舗同一性を分類 → 必要な一次照合 → データ差分**。最終結論を作ってからJevに追認させる工程ではない。

|---|---|
|前段|5サイト1,186記事を分類済み。再取得・再送していない|
|リンク収集|695 URLを計画化。取得572、失敗123を状態付き保存|
|今回のJev|572ページ＋記事/既存施設96組＝668対象、88通信|

|同一性分類|同一候補30、別支店等58、商業施設/目印7、曖昧1。すべて未確定の振分け|
|処理実測|Jev実行51.169秒、通信累計48.234秒。収集・人による確認・実装・保存を含む総作業時間ではない|
|使用量推定|今回$0.048037038、追加承認枠の累計$0.103538064。実請求明細との突合は未実施|

Jevから直接地図を変更した件数は0。一次資料・支店・位置を別途照合して15件を採用した。判定確率は正答率ではなく、今回も商業施設とテナント、複数支店の誤同定候補があった。モデルの分類精度を検証済みとはしない。

## 再現性・誤反映対策

- `data-sources/facility-evidence-20260925/adoptions.json`：採用する公開事実、公式URL、日付、元ID/追加ID、照合理由。
- 同 `adoption-evidence.json`：一次資料と位置の保存先・SHA-256、変更前後ハッシュ。`holds.json`：確認済みの保留12判断行。
- `scripts/collect-facility-evidence.mjs`：695 URL計画・取得。キャッシュ済みを再取得しない。
- `scripts/triage-facility-evidence.mjs`：`--prepare` / `--run` / `--report`。前段の承認済み実績と累積上限を検査。秘密はローカルの既存DPAPI資格情報だけを使い、Drive/Gitへ入れない。
- `scripts/prepare-facility-followups.mjs`、`prepare-facility-map-followups.mjs`、`fetch-facility-followups.mjs`：本文で実際に案内されていたリンクと明示した追加URLを取得。
- `scripts/index-facility-positions.mjs`：公式案内が参照する地図の店舗/住所の点を抽出。`@緯度,経度`の画面中心を使わない。地域代表点・ビル代表点・入口を区別する。
- `scripts/apply-facility-evidence.mjs`：採用資料の存在、元施設との前提一致、県内市町、名称重複、変更前後ハッシュを確認して差分を適用。2回目も同一結果を検証済み。
- `scripts/report-facility-evidence.mjs`：1,186記事の順序を保持した継続台帳を生成。入れ子の店舗候補をJSON文字列でCSVに保存し、前段CSVの`[object Object]`表示欠落を解消。前段の原JSON・ZIPは改変しない。

位置索引は**変更前のデータ**から作った近傍5施設を照合根拠として保持する。現在の追加済みデータで位置索引を上書きして「以前は無かった」の根拠にしない。再現時は保存された `facility-current-before.json` の状態を用いる。なお新施設の代表点は徒歩入口の検証ではない。

原記事・HTML・Jev入力/生応答・継続台帳は非公開Driveに保存し、本文・画像を公開Gitへ転載しない。前段のアーカイブと今回のアーカイブを組み合わせて再現する。

## 未解決の情報と次の順序

固定40件や業態別少数枠には戻さない。全件台帳から自治体を巡回し、閉店→開店→移転等、既知チェーンの手掛かりが無い候補を先、記事日付降順、キー順という既存の順序を維持する。

1. `continued-review-queue.csv/json` の新しい根拠列を使う。83告知/176現行案内の候補を確認し、採用済みIDを繰り返し数えない。記事に連なる現行案内の採用だけで、その記事の開閉店イベント全体を完了扱いしない。
2. 旧ミコー/現マルキュウのような同所在地の旧店、ウォンツ旧新支店、海都などの元ID付き閉店・移転候補を優先。旧店を根拠なしに削除しない。
3. OZ宇部・下松瑞穂、ふくぱんの店舗販売終了、エミール中央店等は一次資料に変更情報があっても元店舗IDを確定できていない。閉店済みを営業中の新店として足さず、住所・旧名称で照合する。
4. kikiの公開位置不足、PilatesGenieの地域代表点、SuouCoffeeFactoryのサービス種別など、何を確定すれば採用できるかを `holds.json` から再開する。
5. 取得失敗123 URL、JavaScriptで本文が表示される店舗サイト、公式SNS/LINEのみの候補は別の残件。拒否や認証を迂回しない。既存クレジットの残枠を超える実行・自動課金はしない。

地域記事5サイト・期間2024年以降という前段の範囲に依存する。県内全店、新店すべて、SNS全体の網羅性はない。GPTChatの2,472件版は未回収のまま、再利用件数へ加算していない。
