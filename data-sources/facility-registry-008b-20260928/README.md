## 対応

学校・保育・医療・福祉・郵便局・公共施設の現行名簿と、施設固有の公的地点・完全住所を照合。店舗は元の独立した支店名・電話・完全住所・固有URLを公式案内へ接続する。位置はPoint50m以内、Polygon/MultiPolygonは穴を除く元形状内部に限る。古い位置資料は同一性の補助に限定し、現況は現行資料で別に確認する。近接するブランド名だけ、地図表示中心、台帳への不掲載だけでは採用しない。

訂正は掲載名称等12件と状態25件。病院から診療所への分類訂正3件を名称訂正に含み、二重計上しない。学校の閉校12・休校5、図書館旧所在地の閉館4、郵便局の一時閉鎖1、飲食店の旧店閉鎖1・一時休業1、パン屋の店舗営業終了1を区別。日不明・月単位の日付はその精度を保持し、新店の開業日を旧店の閉店日へ流用しない。

元ID・座標・形状・元出典・605追加施設と以前の2,731件の判断を保持。同一施設や同住所サービスの重複が疑われる38件は新規確認から除外。丸亀製麺宇部際波の2ID、フジ西宇部の2IDなども保留。別サービスや後利用施設の営業まで閉鎖扱いにしない。

## ファイル

- reviews.json：掲載照合と根拠。閲覧日と資料基準日を区別。
- updates.json：明記された閉鎖・休止の根拠と日付精度。
- holds.json：残件の元ID・不足理由・次に必要な証拠。
- batch.json：件数・元データと入力のハッシュ。

原本、独立した原資料監査、処理、保留、再現証拠は別の正式原本に保存する。公開データには公表済み施設情報と証拠だけを収録し、原資料に埋め込まれた地図APIキー等は含めない。元の自治体データ、国土数値情報、行政名簿および運営者ページの出典URLを各記録に保持する。

## 検証

`node scripts/apply-facility-registry-008b.mjs` は適用前のドリフトを検査。`--apply` は再適用しても同じ結果となる。型検査と `npm run build` により既存判断保持・候補除外・日付精度・限定的な医療分類変更・表示を検証する。再集計は build-facility-progress-ledger → refresh-facility-routing-inputs → build-facility-workboard の順。既存記事判断を初期化するprepare処理は使用しない。

台帳・公式一覧への掲載確認は当日の営業・受入・利用可否・入口の保証ではない。
