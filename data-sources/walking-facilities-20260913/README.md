# 徒歩圏と施設候補の照合資料（2026-09-13）

GitHubへ受領済みの国のバス停・施設データと、R2に配信された事前計算済みの道路範囲を照合する。

- 元のバス停・施設ID、分類判断、形状を変更しない。参考施設5件を除く1,130レコードが候補判定の対象。
- 各道路線分と施設の代表点・登録範囲の最近接点を求め、25m以内にある組を候補とする。複数の該当道路がある場合は、到達距離が最小の組を採用する。
- 時間は、その道路上の地点までの事前計算距離を時速4kmに換算する。坂道の換算は受領値をそのまま用いる。施設との隙間を歩けるとはみなさず、出入口・横断・工事・私有地の通行可否は未確認として表示する。
- 点・建物外周・敷地範囲・中庭などの穴・複数棟を扱う。道路が建物範囲を横切る場合も境界との交点を照合する。形状の内側全体に歩行経路を作らない。
- 全15分のデータから候補の到達距離を決めた後、5/10/15分で絞り込む。時間を延ばすと候補集合は必ず包含関係となり、同じ候補の所要時間も変わらない。
- 0件は登録された施設・道路と上記条件で候補が見つからないという意味で、近隣に施設がないという断定ではない。重複した施設レコードは統合しない。

`cases.json`は代表地点と確認した件数、`audit.json`は候補ごとの元ID・到達距離・近接座標・隙間と時間別集計。`scripts/audit-baked-facilities.mjs`で再生成する。テストは `scripts/test-baked-facilities.mjs`。

`catchments/`の最初の6地点は2026-09-12のPR統合時に取得して照合済みのR2サンプルを、バイトを変更せず引き継いだもの。山口駅・徳山駅前の2地点は2026-09-13に同じ配信元から追加取得した。配信元は `https://pub-64cdb45739c446ef86342de34ccd47a6.r2.dev/data/walk/`。ファイル名は計算起点IDで、SHA-256は`audit.json`に記録する。全県の徒歩圏を再取得・再生成した記録ではない。
